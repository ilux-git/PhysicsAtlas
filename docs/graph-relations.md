# Связи графа

Граф — производное представление базы знаний. Узлы — все семь типов сущностей (`quantity`, `equation`,
`law`, `unit`, `dimension`, `condition`, `derivation`). Рёбра типизированы; тип задаёт смысл, а не только
линию на экране.

## 1. Реестр отношений

| Отношение | Откуда → Куда | Происхождение | Смысл |
|---|---|---|---|
| `appears_in` | Quantity → Equation | производное из AST | величина участвует в уравнении |
| `expresses` | Equation → Law | производное из `lawRefs` | уравнение — математическая форма закона |
| `derived_from` | Equation → Equation | производное из выводов | целевое уравнение выведено из исходного |
| `has_unit` | Quantity → Unit | производное из `unitIds` | допустимая единица величины |
| `has_dimension` | Quantity → Dimension | производное из `dimensionId` | размерность величины |
| `equivalent_unit` | Unit ↔ Unit | производное из группы | допустимая конвертация единиц |
| `requires_condition` | Equation/Law → Condition | производное из `conditionRefs` | условие применимости |
| `has_derivation` | Equation → Derivation | производное из вывода | у уравнения есть вывод |
| `produces` | Derivation → Equation | производное из вывода | вывод порождает целевое уравнение |
| `related_to` | любое ↔ любое | **авторское** | только когда точного отношения нет |

`related_to` в текущем контенте не используется: все связи выражаются точными отношениями. Если появится
соблазн применить `related_to` для физической зависимости или выводимости — это ошибка модели.

## 2. Что не смешивается

| Смысл | Отношение |
|---|---|
| физическая зависимость | `expresses`, `requires_condition` |
| математическая выводимость | `derived_from`, `has_derivation`, `produces` |
| участие величины в формуле | `appears_in` |
| связь закона и его записи | `expresses` |
| структурная принадлежность | `has_unit`, `has_dimension` |
| конвертируемость | `equivalent_unit` |

Например, `F = ma` и `a = F/m` — два уравнения, между ними `derived_from`; `F` участвует в обоих через
`appears_in`; закон только один, и оба уравнения его выражают.

## 3. Правила вывода

Логика — `src/knowledge/derive.ts`, идентификатор ребра — `kind:from->to`:

- `appears_in` — обход AST (обе части и альтернативные формы используют одинаковый набор переменных;
  выводится по основной форме);
- `expresses` — каждый `lawRef`;
- `has_unit`, `has_dimension` — поля величины;
- `requires_condition` — `conditionRefs` уравнения и закона;
- `has_derivation` — только исходное уравнение; `produces` — целевое; `derived_from` — обратное ребро
  целевое → исходное;
- `equivalent_unit` — все упорядоченные пары единиц одной размерности и одной группы конвертации.

Рёбра дедуплицируются и сортируются по `(kind, from, to)`, что делает граф детерминированным.

## 4. Запросы

`src/engines/graph/build.ts`:

- `buildGraph(kb)` — исходящие/входящие списки смежности;
- `neighbors(graph, id, filter)` — соседи с направлением, фильтром типов рёбер и типов сущностей;
- `neighborhood(graph, id, radius, filter)` — BFS-окрестность (радиус 0–4), расстояния в шагах и только
  индуцированные рёбра;
- `filterEntities`, `edgesOfKind` — выборки;
- `graphIntegrity(graph)` — контроль, что все концы рёбер существуют.

Окрестность обходит рёбра в обе стороны: исследование не обязано следовать только «вперёд» по смыслу.

## 5. Поиск

`src/engines/graph/search.ts` строит индекс полей: ID, названия `ru/en`, альтернативные названия, символ,
нормализованная формула (`displayLatex`, альтернативные формы, инфиксная запись AST), описание.

Ранжирование: точный ID → точный символ → точное название → точный альтернатив(ный) вариант → префиксы →
подстрока формулы → подстрока описания. Порядок при равенстве: тип сущности (величина → уравнение → закон
→ единица → размерность → условие → вывод), затем русское название. Формулы нормализуются так, что
`F = ma`, `F=ma` и `\frac`-запись ищутся одинаково.

Поиск не стеммирует русские слова: это подстрочный поиск. Ограничение зафиксировано в
`docs/content-status.md`.

## 6. Раскладка карты

`src/engines/graph/layout.ts` — чистая детерминированная функция:

- фокус в центре;
- узлы группируются по расстоянию BFS, сортируются по ID и располагаются на кольцах радиуса `hop × 150`;
- одинаковый вход даёт побайтово одинаковый выход (тест);
- рёбра включаются только если оба конца попали в окрестность.

Панорама и масштаб — состояние просмотра, а не раскладки. Поэтому карта не «прыгает» при перетаскивании и
зуме. Двойной клик по узлу увеличивает глубину на 1 (до 4).

## 7. Подсветка маршрута

`pathHighlight(path)` возвращает узлы и рёбра найденной цепочки: целевая величина, уравнения, их
переменные, условия. UI применяет подсветку к карте и приглушает остальные узлы. Выбор другого узла
сбрасывает подсветку — состояние маршрута не должно переживать смену контекста.
