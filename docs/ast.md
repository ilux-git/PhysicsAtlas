# AST и математическая модель

LaTeX в атласе — только представление. Семантику формулы задаёт AST; поиск путей, проверка размерностей и
вычисления работают исключительно с ним.

## 1. Узлы AST

```ts
type AstNode =
  | { type: 'variable'; quantityId: string }
  | { type: 'constant'; name: string; value: number; display?: string }
  | { type: 'add' | 'subtract' | 'multiply' | 'divide'; left: AstNode; right: AstNode }
  | { type: 'power'; base: AstNode; exponent: number }
  | { type: 'sqrt'; arg: AstNode }
  | { type: 'negate'; arg: AstNode };
```

- `variable` ссылается на канонический ID величины, а не на букву. Буква — свойство величины.
- `constant` — числовая константа; в текущей модели безразмерная. Появление размерных констант потребует
  расширения схемы, а не «договорённости в коде».
- `power.exponent` — целое число от −12 до 12. Это ограничение парсера и размерностного анализа.
- `sqrt` — отдельный узел; корни произвольной степени не поддерживаются.
- Другие операции (тригонометрия, логарифмы, интегралы) в модель не входят.

## 2. Грамматика формул

Парсер (`src/engines/ast/parse.ts`) принимает ограниченный инфиксный язык:

```text
expr    := term (('+' | '-') term)*
term    := unary (('*' | '/') unary | implicit unary)*
unary   := ('-' | '+') unary | power
power   := primary ('^' integer)?
primary := number | identifier | 'sqrt(' expr ')' | '(' expr ')'
```

- Допустимы латинские идентификаторы; каждый должен быть связан с величиной через таблицу символов.
- **Неявное умножение** разрешено, потому что школьные записи пишут `m a` и `2 m a`; `ma` — уже один
  идентификатор и должен быть объявлен. Juxtaposition binds **tighter** than explicit `*` and `/`.
- Юникод нормализуется: `−` → `-`, `· × ⋅` → `*`, `÷` → `/`, `√` → `sqrt`.
- `sqrt` — единственная функция. Любая другая функция — ошибка `unknown-function`.
- Степень — целое число от −12 до 12; `m^1.5` отвергается с `invalid-exponent`, `a^2^3` — как
  `unexpected-token`.
- Уравнение (`parseEquation`) требует ровно один `=` и непустые части.
- Пользовательский код не исполняется: строка `process.exit(0)` отвергается токенизатором/парсером.

### Приоритет операций (снизу вверх)

| Уровень | Операции | Ассоциативность |
|---|---|---|
| 1 | `+`, `-` | слева |
| 2 | `*`, `/` | слева |
| 3 | неявное умножение (соседство) | слева |
| 4 | унарные `+`, `-` | префикс |
| 5 | `^` (целый литеральный показатель) | по правилу записи |
| 6 | атомы, скобки, `sqrt(...)` | — |

Следствия, закреплённые тестами:

- `m a` = `m·a`; `a / b c` = `a / (b·c)`; `m a / t` = `(m·a) / t`;
- `-a^2` = `−(a²)`; `(-a)^2` = `(−a)²`; `a^-2` допустимо;
- `ma` без объявленного символа — ошибка `unknown-symbol`;
- `sqrt` требует скобок: `sqrt(a)`, не `sqrt a`.

Печать обратно в строку — `astToInfix` (в том же модуле) с приоритетным расставлением скобок:
сумма под произведением/делением, правый операнд деления, основание степени и отрицание под степенью
печатаются в скобках. Тест проверяет `parse(print(ast)) === ast` для представительного набора формул.
Именно эта строка показывается в шагах Find Path и в диагностике; она не является исходным LaTeX.

Ошибки типизированы: `FormulaParseError.code ∈ {empty-expression, unexpected-character, unexpected-token,
unexpected-end, unknown-symbol, unknown-function, missing-parenthesis, invalid-exponent, invalid-equation}`.

## 3. Структурная проверка

`validateAst` проверяет:

- глубину вложенности (по умолчанию ≤ 16);
- существование величины для каждого `variable`;
- конечность констант;
- деление на литеральный ноль;
- целочисленность показателя степени.

Она не проверяет размерности и не доказывает физику — это разные слои.

### Проверка отображения

`displayLatex` не считается доверенным только потому, что содержит нужные символы. Валидатор
переводит поддерживаемое подмножество LaTeX в инфиксную запись (`src/engines/ast/latex.ts`:
`\frac`, `\sqrt`, `\cdot`, `\times`, `\div`, `\left`/`\right`, `^{...}`, фигурные группы) и
разбирает обе стороны тем же парсером. Затем `astEquals` сравнивает результат с сохранённым AST
основной формы и каждой альтернативной формы.

- `display-ast-mismatch` — отображение разбирается, но описывает другую формулу (`F = m + a` при
  AST `F = ma`);
- `display-latex-unsupported` — команда вне поддерживаемого подмножества;
- `display-parse-error` — отображение не разбирается (например, неизвестный символ);
- `alternative-variable-mismatch` — набор величин альтернативной формы отличается от основной.

Наличие символов в строке остаётся дополнительной проверкой, но не доказательством. Генерация
LaTeX из AST не используется: школьная запись важна для чтения, поэтому авторский LaTeX
проверяется структурно, а не заменяется машинным.

## 4. Размерности

Размерность — вектор целых показателей по `L, M, T, I, Th, N, J`
(`src/engines/dimensions.ts`):

| Узел | Правило |
|---|---|
| `variable` | размерность величины |
| `constant` | безразмерная |
| `add`/`subtract` | размерности обязаны совпадать, иначе `add-mismatch` |
| `multiply`/`divide` | показатели складываются/вычитаются |
| `power(n)` | показатели умножаются на `n` |
| `sqrt` | показатели делятся на 2; нечётный показатель — `sqrt-odd-exponent` |
| `negate` | размерность не меняется |

`checkEquationDimensions(lhs, rhs)` возвращает `{ok, lhs, rhs, message}` и используется и валидатором, и
карточкой, и поиском путей.

Размерностная совместимость **не** доказывает физическую корректность: `F = 2ma` проходит проверку
размерностей, но не является вторым законом Ньютона. Поэтому статусы разделены.

## 5. Численное вычисление

`evaluate(ast, values)` принимает значения в СИ и возвращает число. Ошибки типизированы:

| Код | Причина |
|---|---|
| `missing-value` | нет значения величины; ноль не подставляется |
| `division-by-zero` | знаменатель равен нулю |
| `domain-error` | корень из отрицательного числа, ноль в отрицательной степени |
| `overflow` | результат не является конечным числом |

`evaluateEquation` возвращает значения обеих частей и их разность; тесты используют это для проверки
согласованности подстановок.

## 6. Ограниченное решение уравнения

`src/engines/ast/solve.ts` выражает величину из уравнения, если она встречается **ровно один раз**.
Алгоритм идёт от корня AST к вхождению величины и применяет обратные операции:

| Узел | Обратное действие | Предусловие |
|---|---|---|
| `+` / `−` | перенос слагаемого | — |
| `×` | деление на множитель | множитель ≠ 0 |
| `/` (в числителе) | умножение на знаменатель | знаменатель ≠ 0 (домен исходной записи) |
| `/` (в знаменателе) | деление на другую часть | другая часть ≠ 0 |
| `x²` | `sqrt` | правая часть ≥ 0; берётся неотрицательный корень |
| `x^n, n ∉ {1,2}` | — | не поддерживается |
| `sqrt(x)` | возведение в квадрат | правая часть ≥ 0 |
| `negate` | смена знака | — |

Предусловия возвращаются как структурированный список (`nonzero`, `nonnegative`, `two-roots`) и
попадают либо в существующие условия базы знаний (по `quantityId`), либо в предупреждения пути.

Если величина встречается дважды, стоит по обе стороны уравнения или требует степени выше второй,
результат — `{ok: false, reason}`. Это осознанное ограничение: атлас не имитирует CAS.

## 7. Проверка выводов

Для каждой записи `derivation` валидатор:

1. берёт целевую величину из изолированной стороны целевого уравнения;
2. применяет `solveFor` к исходному уравнению;
3. сравнивает полученный AST с целевой стороной через `astEquals`.

Совпадение означает, что шаги приводят к целевой форме **структурно**. Символического доказательства и
проверки каждого шага по отдельности нет; поэтому `verificationStatus` у всех выводов — `structural`.

## 8. Что не реализовано

- Общий символьный решатель (несколько вхождений, системы уравнений, тригонометрия).
- Интегралы, производные, пределы.
- Векторная алгебра: векторные величины участвуют как модули, с явной оговоркой в форме уравнения.
- Размерные константы в AST.
- Произвольные корни (`root(n)`).
- Упрощение выражений и проверка алгебраической эквивалентности за пределами `astEquals`.
