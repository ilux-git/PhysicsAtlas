# Математический движок

Движок состоит из четырёх независимых частей: размерности, единицы, AST (разбор/вычисление/решение) и
поиск вычислительных путей. Все функции чистые и не зависят от React.

## 1. Размерности

- Размерность — `Record<'L'|'M'|'T'|'I'|'Th'|'N'|'J', number>`.
- Сложение и вычитание требуют равенства размерностей; умножение/деление складывают/вычитают показатели;
  степень умножает, корень делит пополам.
- Форматирование: `L·M·T⁻²`, безразмерная — «1 (безразмерная)».
- Размерностная совместимость — необходимое, но не достаточное условие корректности. Это прямо влияет на
  разделение статусов уравнения.

### Проверка уравнения

`checkEquationDimensions(lhs, rhs, quantityDimensions)` возвращает `ok`, вычисленные размерности и
человекочитаемое сообщение. Ошибки внутри AST (сложение несовместимых величин, корень из нечётных
показателей) не бросаются наружу как исключения в UI: они превращаются в сообщение статуса.

## 2. Единицы

Перевод `convertUnit(value, fromId, toId, units)` выполняет проверки в фиксированном порядке:

1. обе единицы существуют (`unknown-unit`);
2. коэффициенты положительны и конечны, смещения конечны (`invalid-unit`);
3. размерности совпадают (`dimension-mismatch`);
4. группы конвертации совпадают (`group-mismatch`);
5. входное и выходное значения конечны (`non-finite`).

Формула: `SI = value × factor + offset`; результат `= (SI − to.offset) / to.factor`.

Почему группа обязательна: одинаковой размерности недостаточно (энергия и момент силы имеют одинаковую
размерность `M·L²·T⁻²`, но не взаимозаменяемы). Группы в контенте заданы явно.

Смещение поддерживается движком и проверяется тестом на синтетических °C/K; в контент единицы со смещением
не добавлены — это ограничение контента, а не движка.

## 3. Статусы уравнения

Независимые величины:

| Статус | Как получен | Где виден |
|---|---|---|
| структурный | `validateAst` по AST и переменным | карточка/инструменты |
| размерностный | `checkEquationDimensions` | карточка/инструменты |
| физическая экспертиза | авторский JSON (`standard-form`, `draft`, `needs-review`) | карточка |
| условия | авторский JSON (`explicit`, `missing`) | карточка |

Никакого единого `valid` нет. `F = 2ma` получает «структура: ок», «размерности: ок», но
«экспертиза: черновик», если так размечено; тест фиксирует, что проверка размерности не повышает
физический статус.

## 4. Проверка выводов

`verifyDerivation(derivation, source, target, kb)`:

1. находит целевую величину (изолированную сторону целевого уравнения);
2. решает исходное уравнение относительно неё;
3. сравнивает AST с целевой стороной.

Результат — `{ok, message}`. Он показывается в карточке вывода и в инструменте «Вывод». Статус `structural`
означает именно структурное совпадение, а не символьное доказательство.

## 5. Поиск вычислительных путей

`findPaths(kb, options)` — обратный поиск по уравнениям.

### Вход

- `targetId` — целевая величина;
- `knownIds` — известные величины;
- `values` — необязательные значения с единицами (переводятся в СИ);
- `confirmedConditionIds` / `violatedConditionIds` — решения пользователя по условиям;
- `depthLimit` (1–5, по умолчанию 3), `maxPaths` (1–8), `targetUnitId`.

### Алгоритм

1. Для каждой величины заранее вычисляется список уравнений, из которых она выражается
   (`solveFor(...).ok`). Кандидаты сортируются: сначала уравнения, где величина стоит изолированно
   (`I = U/R`), затем по числу переменных, затем по ID.
2. Целевая величина разрешается рекурсивно: для каждого неизвестного из выражения решателя ищется
   подцепочка. Промежуточные результаты добавляются в доступные для следующих неизвестных.
3. Цикл предотвращается множеством посещённых величин в текущей ветке; глубина ограничена.
4. Собираются до `maxPaths` различных цепочек (по последовательности «уравнение → величина»).
5. Каждый шаг несёт AST выражения, предусловия и (при наличии значений) численный результат в СИ.
6. Условия уравнения добавляются в путь; предусловия решателя сопоставляются с существующими условиями
   (`nonzero` по величине), иначе становятся предупреждением.

### Статусы пути

- **допустимый** — все условия подтверждены, нет предупреждений, все уравнения `standard-form`;
- **условно допустимый** — есть неподтверждённые условия, неизвестная физическая экспертиза или
  математическое ограничение без явного условия;
- **недопустимый** — условие отмечено нарушенным, либо численный расчёт упал (например, деление на ноль
  при подстановке).

Векторные величины в форме модулей дают **примечание**, а не понижение статуса: это интерпретация записи,
а не невыполненное условие. Примечание всегда показывается.

### Численный расчёт

Шаги идут в порядке зависимостей. Значения известных величин переводятся в СИ; результат каждого шага
подставляется в следующие. Если значения не заданы, цепочка остаётся символьной. Ошибки вычисления
(`division-by-zero`, `domain-error`, `missing-value`, `overflow`) не скрываются: путь становится
недопустимым с причиной.

### Почему путь не найден

Движок различает два случая и сообщает их текстом: нет уравнения, выражающего целевую величину, либо при
заданной глубине не хватает известных величин. Это соответствует требованию не выдавать ответ любой ценой.

## 6. Ошибки и пределы

| Ситуация | Поведение |
|---|---|
| деление на ноль в формуле | структурная ошибка AST/валидатора; вычисление невозможно |
| деление на ноль при подстановке | путь недопустим, причина показана |
| корень отрицательного числа | `domain-error` |
| неизвестная величина в AST | ошибка валидации, сборка блокируется |
| размерности не совпадают | ошибка валидации уравнения |
| условие нарушено | путь недопустим |
| условие не подтверждено | путь условно допустим |
| величина встречается дважды | решатель отказывает с причиной |
| степень ≠ 1, 2 | обратное преобразование не поддерживается |
