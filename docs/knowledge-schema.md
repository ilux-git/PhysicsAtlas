# Схема базы знаний

База знаний — девять JSON-массивов в `src/knowledge/data/`:

| Файл | Содержимое |
|---|---|
| `dimensions.json` | размерности (векторы показателей) |
| `units.json` | единицы измерения |
| `quantities.json` | физические величины |
| `laws.json` | законы |
| `conditions.json` | условия применимости |
| `equations.json` | уравнения (AST + отображение) |
| `derivations.json` | выводы формул |
| `domains.json` | разделы физики |
| `sources.json` | источники |

Схемы описаны Zod в `src/domain/schemas.ts`; типы — в `src/domain/types.ts`. Соответствие «схема ↔ тип»
проверяется компилятором в загрузчике (`src/knowledge/index.ts`): результат `safeParse` присваивается
типизированному `KnowledgeInput`.

## 1. Общие правила

- **ID** — стабильные, машинные, языково- и классно-независимые: `q.mass`, `eq.ohm.local`, `law.ohm`,
  `unit.volt`, `dim.voltage`, `cond.steady-current`, `der.ohm.current`. Префикс обязан соответствовать типу
  (`q.`, `eq.`, `law.`, `unit.`, `dim.`, `cond.`, `der.`).
- **slug** — человекочитаемый машинный идентификатор без префикса.
- **Локализация**: `{"ru": "...", "en": "..."}`; `ru` обязателен, `en` необязателен и подставляется
  фолбэком. Один объект — один канонический ID, без копий по языкам или классам.
- **Уровни**: `levelPresentations` — частичная карта `"7-8" | "9" | "10-11"`. Каждая презентация содержит
  `summary` и опционально `details`, `mathNote`, `extraLinks`. Один объект получает разные изложения, а не
  дубликаты.
- **Проверка**: `review` разделён на два независимых поля:
  - `formulation ∈ {"standard-school", "definition", "derived", "draft"}` — тип и происхождение записи;
  - `expert ∈ {"none", "requested", "completed", "rejected"}` — состояние независимой экспертизы.
  `reviewer` и `reviewedAt` обязательны только для `completed`/`rejected`; для `completed` также нужен
  хотя бы один источник. `standard-school` никогда не означает «проверено экспертом».
- **Домены и источники**: `domains` и `sources` — массивы ID; все ссылки обязаны существовать.

## 2. Размерность (`dimension`)

```json
{
  "id": "dim.force",
  "kind": "dimension",
  "slug": "force",
  "name": { "ru": "Сила", "en": "Force" },
  "aliases": [],
  "description": { "ru": "..." },
  "levelPresentations": {},
  "domains": ["domain.mechanics"],
  "sources": ["source.si-brochure-2019"],
  "review": { "formulation": "standard-school", "expert": "none" },
  "exponents": { "L": 1, "M": 1, "T": -2, "I": 0, "Th": 0, "N": 0, "J": 0 }
}
```

`exponents` — целочисленный вектор по базовым размерностям `L, M, T, I, Th, N, J`. Все семь ключей
обязательны; нули значат отсутствие вклада. Размерность без показателей — «безразмерная».

## 3. Единица (`unit`)

| Поле | Тип | Смысл |
|---|---|---|
| `symbol` | string | обозначение (`m`, `km/h`, `Ω`) |
| `dimensionId` | ref | размерность единицы |
| `system` | `SI \| non-SI \| accepted` | системность |
| `factor` | number > 0 | множитель к СИ |
| `offset` | number | смещение к СИ (по умолчанию 0) |
| `conversionGroup` | string | группа физически взаимозаменяемых единиц |

Перевод: `SI = value × factor + offset`, обратно `value = (SI − offset) / factor`. Единицы одной
размерности, но разных `conversionGroup`, переводить запрещено: одинаковой размерности недостаточно.

## 4. Величина (`quantity`)

| Поле | Тип | Смысл |
|---|---|---|
| `symbol` | string | латинский символ; уникален в базе |
| `quantityKind` | `scalar \| vector` | скалярная/векторная |
| `dimensionId` | ref | размерность |
| `unitIds` | ref[] | допустимые единицы |
| `preferredUnitId` | ref | единица по умолчанию; обязана входить в `unitIds` |
| `definition` | LocalizedText | определение |

Размерность каждой единицы из `unitIds` обязана совпадать с размерностью величины. Символы величин
уникальны: иначе формулы и поиск становятся неоднозначными.

## 5. Уравнение (`equation`)

| Поле | Тип | Смысл |
|---|---|---|
| `lhsAst`, `rhsAst` | AST | каноническая математическая форма |
| `displayLatex` | string | только отображение |
| `alternativeForms` | AlternativeForm[] | алгебраически эквивалентные записи |
| `lawRefs` | ref[] | законы, которые выражает уравнение |
| `conditionRefs` | ref[] | условия применимости |
| `form.kind` | `magnitudes \| vectors` | запись через модули или векторная |
| `form.note` | LocalizedText? | оговорка к форме записи |
| `review.expert` | status | экспертная проверка (общая для сущности) |
| `conditionsStatus` | `explicit \| missing` | заявлено ли условие |

Правила валидатора:

- каждая переменная AST ссылается на существующую величину;
- `displayLatex` структурно разбирается и совпадает с AST каждой формы (не только по набору символов);
- набор величин каждой альтернативной формы совпадает с основной;
- размерности `lhsAst` и `rhsAst` совпадают (а также для каждой `alternativeForm`);
- `conditionsStatus = "explicit"` требует непустого `conditionRefs`;
- `"missing"` при непустых ссылках даёт предупреждение;
- ID альтернативных форм уникальны.

`variables` уравнения не хранится: выводится из AST.

## 6. Закон (`law`)

Содержит `conditionRefs`, описание и уровневые изложения. `equationRefs` не хранится: строится из
`lawRefs` уравнений. Закон без математической формы допустим, но карточка покажет пустой список.

## 7. Условие (`condition`)

| Поле | Тип | Смысл |
|---|---|---|
| `structured` | объект? | машинно-читаемое ограничение |
| `structured.type` | `frame \| constancy \| direction \| nonzero \| material \| regime` | вид |
| `structured.quantityId` | ref? | к какой величине относится |
| `structured.value` | string? | значение/режим |
| `structured.note` | LocalizedText? | пояснение |

Структурные условия используются карточками и поиском путей: `nonzero` по известному нулевому значению
автоматически переводит условие в «нарушено». Условия, требуемые законом, добавляются к пути наряду с
условиями уравнения и получают атрибуцию `requiredBy`.

## 8. Вывод (`derivation`)

| Поле | Тип |
|---|---|
| `sourceEquationId`, `targetEquationId` | ref, разные уравнения |
| `steps[]` | `order`, `description`, `operation`, `displayFrom`, `displayTo`, `precondition?` |
| `preconditions` | ref[] условий |
| `verificationStatus` | `draft \| structural` (значение `verified` удалено) |

Валидатор проверяет порядок шагов (1..n), существование ссылок и **структурное совпадение**: решатель
выражает целевую величину из исходного уравнения, и результат сравнивается с целевым AST. Это не
символическое доказательство; статус `structural` так и говорит.

## 9. Раздел и источник

`domain`: `id`, `slug`, `name`, необязательное `description`.
`source`: `id`, `type ∈ {standard, textbook, curriculum, reference}`, `title`, авторы/издание/URL/
`note` — всё необязательное, кроме `title`. Библиографические данные, которых нет, не выдумываются;
неуверенность фиксируется в `note`.

## 10. Инварианты, которые нельзя нарушать

1. Один физический объект — один ID.
2. Один объект — разные уровни и языки через поля, а не через копии.
3. Никаких дублирующих фактов: переменные, обратные ссылки и рёбра выводятся.
4. Размерностная совместимость не повышает `review.expert` и не меняет `review.formulation`.
5. Условия применимости не удаляются ради упрощения изложения.
6. Все ссылки существуют и имеют правильный тип.
7. Ошибки валидации блокируют сборку; предупреждения — нет.

## 11. Как расширять

1. Добавить сущность с уникальным ID и всеми обязательными полями.
2. Сослаться на существующие размерности/единицы/условия либо добавить их.
3. При необходимости добавить уравнение с AST и `displayLatex`.
4. Запустить `pnpm validate` и `pnpm test`.
5. Убедиться, что `displayLatex` содержит символы всех переменных.
6. Не добавлять `variables`/`equationRefs` руками — их строит загрузчик.
