# Архитектура

## 1. Контекст и границы

Physics Atlas — клиентское приложение без сервера. Вся физика — статические данные, вся логика — чистые
функции над этими данными. Это соответствует §12 требований: минимальный стек, отсутствие микросервисов,
графовой БД и инфраструктуры без доказанной необходимости.

Ограничения продукта заданы в §3 требований: нет лабораторий, симуляций, курсов, адаптивного обучения,
больших систем тестирования, соцфункций, профилей, LMS и сложного CAS. Ни одна из этих функций не
реализована.

## 2. Слои и направление зависимостей

```text
┌────────────────────────────────────────────────────────────────────┐
│ UI (React): карта, карточки, поиск, инструменты, состояние, URL     │
└───────────────────────────────┬────────────────────────────────────┘
                                │ доступ только через AtlasContext
┌───────────────────────────────▼────────────────────────────────────┐
│ Engines: AST · размерности · единицы · граф · поиск · пути          │
│           чистые функции, никакого React и никакого DOM            │
└───────────────────────────────┬────────────────────────────────────┘
                                │ типизированные сущности
┌───────────────────────────────▼────────────────────────────────────┐
│ Knowledge: JSON → Zod → проверки → производные рёбра → Atlas       │
└───────────────────────────────┬────────────────────────────────────┘
                                │
┌───────────────────────────────▼────────────────────────────────────┐
│ Domain: типы, схемы, AST, локализация, текстовые утилиты            │
└────────────────────────────────────────────────────────────────────┘
```

Зависимости направлены только вниз. `engines` не импортирует `knowledge`, кроме одной функции
`quantityDimensionsFrom(kb)` в `dimensions.ts`, которая принимает уже собранный `KnowledgeBase`.
UI не вычисляет физику сам: все проверки, пути и конвертации приходят из движков.

## 3. Данные и единый источник истины

1. `src/knowledge/data/*.json` — канонические сущности. Ни один факт о физике не хранится в UI или в
   конфигурации карты.
2. `src/knowledge/index.ts` парсит JSON Zod-схемами. Ошибки схемы становятся диагностиками, приложение
   запускается только если их нет.
3. `src/knowledge/derive.ts` строит рёбра:
   - `appears_in` — из переменных AST уравнения;
   - `expresses` — из `lawRefs`;
   - `has_unit`, `has_dimension` — из полей величины;
   - `requires_condition` — из `conditionRefs` уравнения/закона;
   - `has_derivation`, `produces`, `derived_from` — из записей выводов;
   - `equivalent_unit` — из групп конвертации.
4. `src/knowledge/validate.ts` проверяет ссылки, типы рёбер, AST, размерности уравнений, выводы,
   отображение символов в LaTeX.
5. `buildKnowledgeBase` собирает неизменяемый `KnowledgeBase`: карты сущностей, массивы, рёбра,
   диагностики. Дубликаты ID не затирают первое вхождение и всегда дают ошибку.

Списки `variables` уравнения и `equationRefs` закона не хранятся: это производные данные, чтобы исключить
расхождение между карточкой, графом и поиском.

## 4. Состояние приложения

`src/app/state.tsx`:

- `AppState`: выбранный узел, история выбора, уровень, раздел, глубина, фильтры типов, активная вкладка,
  поисковый запрос, подсветка маршрута, черновик поиска пути.
- `appReducer` — единственное место изменения состояния; фильтры не могут отключить последний тип.
- `AtlasProvider` один раз строит `Graph` и поисковый индекс; они живут столько же, сколько база знаний.
- URL-hash фиксирует `node`, `level`, `domain`, `radius`, `tab`. Это делает карточку ссылаемой и
  восстанавливаемой после перезагрузки. Неизвестный узел в hash заменяется существующим.
- `highlight` не попадает в hash: маршрут — временное состояние исследования.
- История выбора и черновик поиска пути живут в памяти сессии; они не входят в hash и сбрасываются
  при перезагрузке. Кнопка «Назад» возвращает предыдущий объект без нового визита в историю.

## 5. UI

- `Workspace` — шапка (поиск, уровень, раздел), карта с оверлеями фильтров и легенды, правая панель с
  вкладками «Карточка / Формулы / Конвертер / Вывод / Поиск пути».
- `MapCanvas` рисует SVG по результату `layoutNeighborhood`. Раскладка детерминирована: BFS-кольца от
  фокуса, стабильный угловой порядок по ID. Зум и панорама — только состояние вида; они не пересчитывают
  раскладку.
- Фигуры узлов различаются формой **и** цветом (круг, прямоугольник, ромб, треугольник, эллипс,
  параллелограмм), поэтому смысл не кодируется только цветом. Узлы доступны с клавиатуры и имеют
  `aria-label`.
- `Inspector` показывает карточку по типу сущности, раздельные статусы структуры/размерностей/
  формулировки/экспертизы/условий, сгруппированные связи с направлением и явные оговорки.
- Карта объясняет расстояние до узла (число шагов) и направление связи; это подсказки в заголовках
  узлов/рёбер, а не скрытая логика.
- Инструменты используют те же движки, что и карточки; дублирования физической логики в компонентах нет.
- `Formula` рендерит KaTeX-разметку из доверенной статической строки. AST при этом остаётся источником
  математической семантики.

## 6. Статусы: вычисленные vs заявленные

| Статус | Источник | Смысл |
|---|---|---|
| `structuralStatus` | вычисляется `validateAst` при отображении/валидации | AST корректен, переменные существуют |
| `dimensionalStatus` | вычисляется `checkEquationDimensions` | левая и правая части одной размерности |
| `review.formulation` | авторский JSON | тип/происхождение записи |
| `review.expert` | авторский JSON | состояние независимой экспертизы; `completed` требует рецензента, даты и источника |
| `conditionsStatus` | авторский JSON | условия указаны явно или нет |

Статусы никогда не сливаются в одно поле `valid`. Размерностно корректное `F = 2ma` не получает статус
«проверено»: это прямо проверяется тестом `equation.test.ts`.

## 7. Ошибки и деградация

- Ошибка схемы/ссылок/размерностей в JSON → приложение показывает экран «База знаний не прошла проверку» и
  список диагностик; `pnpm validate` возвращает код 1 и блокирует `pnpm build`.
- Предупреждения не блокируют сборку: они видны в баннере и в отчёте валидатора.
- Отсутствие значения при численном расчёте или деление на ноль не подменяются нулём: движок возвращает
  типизированную ошибку, `computation.status` становится `failed`, пользователь видит причину. Условия и
  экспертиза при этом остаются отдельными характеристиками и не «наследуют» чужой вердикт.
- Отсутствие пути объясняется: нет уравнения для целевой величины либо не хватает известных величин при
  заданной глубине.

## 8. Детерминизм и тестируемость

- Все движки — чистые функции без `Date`, `Math.random` и доступа к DOM.
- Раскладка проверяется на побайтовое равенство двух вызовов.
- Поиск сортируется по (score, тип, название); рёбра — по (kind, from, to).
- Тесты покрывают движки, валидатор, поиск, раскладку, сценарии UI и обязательные негативные случаи §14.

## 9. Сборка и зависимости

- Vite 8 (Rolldown), React 19, TypeScript 7, Zod 4, KaTeX 0.19, Vitest 5.
- Один статический бандл ≈ 214 КБ gzip; код-сплиттинг не вводился, порог предупреждения поднят до 800 КБ.
- `pnpm validate` выполняется Node-ом напрямую (встроенное снятие типов), без esbuild/tsx: в песочнице
  дочерние процессы с pipe-каналами запрещены, а esbuild требует именно такой запуск.
- pnpm-store размещён внутри рабочего каталога из-за запрета записи за пределы workspace.

## 10. Осознанные упрощения

- Нет роутера: одна рабочая область и hash-состояние.
- Нет сохранения прогресса, аккаунтов и синхронизации.
- Нет code-splitting и ленивой загрузки KaTeX.
- Локализация данных готова, переключение языка интерфейса не реализовано.
- Карта показывает локальную окрестность, а не весь граф: это требование §10 и защита от «волосатого»
  графа.
